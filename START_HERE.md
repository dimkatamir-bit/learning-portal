# Запуск Learning Portal с нуля на Windows

В этой версии обновлён интерфейс всех страниц сотрудника: регистрация, кабинет, курсы, уроки, тесты, результаты и проверка сертификата. Оформление работает локально; интернет нужен для YouTube-видео. Логика обязательного просмотра и ограничения перемотки сохранена.

## 1. Распакуйте проект

Распакуйте ZIP-архив. Откройте папку `learning-portal`, **в которой виден файл `manage.py`**. Нажмите на адресную строку Проводника, напечатайте `cmd` и нажмите Enter. Откроется Командная строка в нужной папке.

## 2. Установите проект

Копируйте команды по одной, каждый раз дожидаясь окончания предыдущей:

```cmd
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
```

`migrate` создаёт `db.sqlite3` и **автоматически добавляет один курс из пяти разных модулей**, пять модульных тестов и финальный экзамен. Варианты ответов перемешиваются при открытии страницы теста.

В каждом модуле есть отдельный ролик Simon’s Cat для демонстрации видеоплеера. Это **иллюстрация интерфейса**, а не урок по работе с документами. Видео загружается с YouTube только после нажатия «Включить видео»; если встраивание запрещено, откройте ссылку под плеером. Для показа понадобится интернет.

Если нужен доступ к `/admin/`, создайте администратора:

```cmd
.\.venv\Scripts\python.exe manage.py createsuperuser
```

При вводе пароля символы в cmd не появляются — это нормально. Логин администратора — email.

## 3. Запустите сервер

Для создания PDF на Windows требуется установленный Pango (см. ниже). Если MSYS2 UCRT64 уже установлен в стандартную папку, выполните:

```cmd
set "WEASYPRINT_DLL_DIRECTORIES=C:\msys64\ucrt64\bin"
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

Откройте `http://127.0.0.1:8001/` в браузере. Пока сервер работает, окно cmd должно оставаться открытым. Остановка — `Ctrl+C`.

## 4. Проверьте курс

На главной странице зарегистрируйте **обычного сотрудника** (не администратора). После регистрации подтвердите email по ссылке из письма (в локальном режиме письмо видно в cmd, см. раздел ниже). Затем откроется кабинет с курсом `[ДЕМО]`. Нажмите «Начать курс» → изучите модуль 1 → **включите видео и дождитесь его окончания** → «Я изучил материал» → сдайте тест. Так же пройдите модули 2–5: каждый следующий открывается после предыдущего теста. Затем сдайте финальный экзамен. Для проходных 70% в тесте из четырёх вопросов надо ответить верно минимум на три. После финального теста PDF появится в кабинете. Номер новых сертификатов начинается с `cesdrr-`.

## Если курсов нет

Проверьте, что команда запущена **в той же папке**, из которой запускается сервер:

```cmd
cd
.\.venv\Scripts\python.exe manage.py seed_demo_course
.\.venv\Scripts\python.exe manage.py shell -c "from courses.models import Course; print(list(Course.objects.values_list('title', flat=True)))"
```

Если список содержит `[ДЕМО]`, обновите страницу кабинета. Если база и сервер находятся в разных копиях папки `learning-portal`, они используют разные `db.sqlite3`. Работайте в одной папке. Команда `seed_demo_course` восстанавливает удалённый пример, не трогая другие курсы.

Для существующей базы команда `migrate` добавляет ролики только в пустые поля `video_url` демо-модулей. Уже заданные администратором ссылки она не меняет. В модулях с поддерживаемой YouTube-ссылкой кнопка завершения урока и тест открываются после окончания видео во встроенном плеере. Плеер скрывает управление перемоткой и сверяет просмотр с временем на сервере. Если видео заблокировано для встраивания, внешний просмотр **не засчитывается** — администратору нужно заменить ссылку. Любой браузерный учёт просмотра технически можно обойти специальными запросами, поэтому это проверка учебного сценария, а не юридическое доказательство просмотра.

## Если PDF не создаётся на Windows

Для WeasyPrint нужен Pango. Если при проверке

```cmd
.\.venv\Scripts\python.exe -m weasyprint --info
```

появляется `cannot load library 'libgobject-2.0-0'`, установите [MSYS2](https://www.msys2.org/), откройте программу **MSYS2 UCRT64**, запустите там `pacman -S mingw-w64-ucrt-x86_64-pango` и подтвердите установку. Затем в **том же cmd, где будете запускать Django**, выполните:

```cmd
set "WEASYPRINT_DLL_DIRECTORIES=C:\msys64\ucrt64\bin"
.\.venv\Scripts\python.exe -m weasyprint --info
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

Если MSYS2 установлен в другом месте, измените путь к `ucrt64\bin`. Переменная окружения задаётся заново при открытии нового окна cmd.

## Если обновляете старую установку

Сохраните копию **старых** `db.sqlite3` и папки `media`. Не заменяйте их при обновлении: там находятся пользователи, прогресс и PDF. Остановите сервер, скопируйте содержимое нового проекта поверх старого, затем в старой папке выполните `manage.py migrate`, `manage.py seed_demo_course` и `manage.py runserver 127.0.0.1:8001`. Если старая база потеряна и резервной копии нет, данные прежних пользователей нельзя восстановить из ZIP с кодом — они в архив не входили.

## Подтверждение email

После регистрации откроется страница «Подтвердите вашу почту». Пока адрес не подтверждён, курсы и тесты закрыты.

**Проверка на компьютере без SMTP:** по умолчанию Django выводит письмо в окно `cmd`, где работает сервер. Найдите строку с `http://127.0.0.1:8001/email/confirm/…`, скопируйте весь адрес в браузер и нажмите «Подтвердить email». Затем откроется кабинет. Письмо в настоящий почтовый ящик в этом режиме не отправляется.

**Настоящая отправка писем:** нужны SMTP-сервер и учётные данные почты отправителя. До запуска сервера задайте настройки в том же окне cmd. Замените примерные значения данными вашей почты; пароль приложений зависит от почтового провайдера:

```cmd
set "DJANGO_EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend"
set "EMAIL_HOST=smtp.your-provider.test"
set "EMAIL_PORT=587"
set "EMAIL_USE_TLS=1"
set "EMAIL_USE_SSL=0"
set "EMAIL_HOST_USER=your-sender@your-domain.test"
set "EMAIL_HOST_PASSWORD=YOUR_SMTP_PASSWORD"
set "DEFAULT_FROM_EMAIL=Learning Portal <your-sender@your-domain.test>"
set "PUBLIC_BASE_URL=http://127.0.0.1:8001"
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

Для рабочего сервера `PUBLIC_BASE_URL` должен содержать настоящий HTTPS-адрес сайта, доступный сотрудникам. Локальный адрес `127.0.0.1` работает только на компьютере с Django. При SMTP на порту 465 обычно нужен SSL: `EMAIL_USE_SSL=1`, `EMAIL_USE_TLS=0`; точные параметры возьмите у провайдера. Пароли не добавляйте в архив проекта и не присылайте в чат.

Ссылка действует 24 часа; повторная отправка доступна через минуту. Если SMTP временно недоступен, аккаунт сохраняется, а пользователь может запросить письмо снова. Подтверждение выполняется кнопкой на странице, чтобы автоматический просмотр ссылки почтовым сервисом не активировал аккаунт.

После обновления старой базы сотрудникам также потребуется подтвердить email. Суперпользователь может войти в `/admin/` для настройки системы. В админке отображается статус подтверждения. Изменение email сбрасывает его подтверждение.

Демонстрационные видео в пяти модулях показываются как 30-секундные фрагменты исходных YouTube-роликов. После просмотра фрагмента целиком открывается следующий шаг.

## Разрешённые адреса и администратор

Администраторы (is_staff) входят в кабинет и проходят курсы без подтверждения email. Статус владения email при этом не подменяется. Обычные сотрудники подтверждают почту. При регистрации принимаются только точные домены: gmail.com, mail.ru, inbox.ru, bk.ru, list.ru, yandex.ru, yandex.com, ya.ru, outlook.com, hotmail.com, live.com, yahoo.com, icloud.com, proton.me, protonmail.com, rambler.ru, cesdrr.org. Регистр букв не важен. Для изменения списка задайте REGISTRATION_EMAIL_DOMAINS через запятую перед запуском. Администраторов через createsuperuser или админку это ограничение не касается. Проверка домена не доказывает существование конкретного ящика — для этого у сотрудников сохраняется подтверждение почты.
