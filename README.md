# Learning Portal — версия для пилотного запуска

Сотрудник регистрируется и подтверждает email ссылкой из письма, затем изучает модули по порядку, сдаёт тесты, затем финальный экзамен и получает PDF с QR. Проверка UUID сертификата открыта без входа; PDF доступен только владельцу. Интерфейс на русском и адаптирован для компьютера и телефона: понятные статусы модулей, прогресс и следующий шаг на каждой странице. Bootstrap 5.3.3 и стили включены в архив и работают без CDN.

## 1. Установка с нуля на Windows

Распакуйте архив и откройте PowerShell **в папке `learning-portal`, где находится `manage.py`**. Краткая инструкция без технических подробностей есть в `START_HERE.md`. Выполняйте команды по очереди:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

Затем откройте `http://127.0.0.1:8001/`. В `http://127.0.0.1:8001/admin/` войдите под email и паролем, созданными в `createsuperuser`. Пароль в PowerShell при вводе не отображается.

Для проверки учебного сценария зарегистрируйте **отдельного обычного сотрудника** на главной странице (можно в приватном окне браузера). Откройте курс `[ДЕМО]`, пройдите по порядку пять разных модулей и их тесты, затем финальный экзамен. Варианты ответа перемешиваются при каждом открытии теста; для проходных 70% в тесте из четырёх вопросов нужно ответить верно минимум на три. Проверьте PDF в кабинете и публичную страницу по ссылке из QR. Демо содержит общие примеры: замените его содержание перед настоящей сертификацией сотрудников.

Миграции `courses.0003_demo_course` и `courses.0004_five_modules` создают один пример курса с пятью модулями, пятью модульными тестами и финальным экзаменом. Миграция `courses.0005_demo_videos` добавляет отдельные иллюстративные YouTube-ролики Simon’s Cat в пустые видеополя демонстрационных модулей; `courses.0006_video_tracking` сохраняет прогресс просмотра. Эти ролики показывают плеер и не являются материалом по работе с документами. В модулях с поддерживаемой YouTube-ссылкой видео требуется досмотреть до конца, чтобы открыть тест. Управление перемоткой скрыто, а сервер сверяет ход просмотра с прошедшим временем; технически подкованный пользователь может подделать клиентские запросы. Команду `seed_demo_course` можно запускать повторно для восстановления отсутствующих модулей и экзаменов; она не удаляет ваши данные. Чтобы добавить свой курс, используйте админку: курс → модули → отдельный экзамен на каждый модуль → финальный экзамен без модуля → вопросы → варианты, отметив правильные. Неполные тесты система не показывает сотруднику.

## 2. Обновление существующей установки

Остановите работающий сервер (`Ctrl+C`). Сначала сделайте копию существующего `db.sqlite3` и папки `media`, если там есть сертификаты. Распакуйте новый архив в другую папку и скопируйте **содержимое** новой папки `learning-portal` поверх старой, согласившись на замену файлов. В архиве нет `db.sqlite3`, `.venv`, `media` — данные остаются в старой папке. **Не удаляйте старую базу:** новый архив не содержит прежних учётных записей, прогресса и сертификатов. Запустите:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo_course
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

Если на старой базе есть **два пользователя с email, отличающимися только регистром букв**, новая миграция сообщит об ошибке уникальности. Сохраните резервную копию базы и исправьте повторяющиеся адреса через админку старой версии, затем снова выполните `migrate`.

### Шаблон сертификата ЦЧССРСБ

Современный PDF-шаблон находится в `templates/certificates/pdf.html`, а формат номера `cesdrr-ГОД-НОМЕР` задаётся в `certificates/services.py`. Если весь проект уже установлен, замените **оба файла** и перезапустите сервер. Миграций для этой замены не требуется. Сертификаты, выпущенные **после** замены, получат новый дизайн и новый номер. Уже выданные номера и сохранённые PDF не изменяются: это выданные документы, их нельзя молча подменять. Пример PDF с условными данными приложен отдельно к архиву. Реальный QR-код строится с адресом проверки вашей установки; для сканирования телефоном настройте доступный HTTPS-адрес до выдачи сертификата.

## 3. PDF на Windows

WeasyPrint нужен Pango. Проверьте:

```powershell
.\.venv\Scripts\python.exe -m weasyprint --info
```

Если видите `cannot load library`, установите [MSYS2](https://www.msys2.org/), откройте **MSYS2 UCRT64**, выполните `pacman -S mingw-w64-ucrt-x86_64-pango`. Затем в PowerShell **перед запуском сервера**:

```powershell
$env:WEASYPRINT_DLL_DIRECTORIES = 'C:\msys64\ucrt64\bin'
.\.venv\Scripts\python.exe -m weasyprint --info
```

Путь исправьте, если MSYS2 установлен в другую папку. [Официальная инструкция WeasyPrint](https://doc.courtbouillon.org/weasyprint/latest/first_steps.html#windows).

## 4. Подготовка Windows Server 2022

Сервер разработки `manage.py runserver` предназначен для локальной проверки. Для реального доступа сотрудников нужны **HTTPS и обратный прокси**, направляющий запросы в локальный Waitress. Не открывайте Waitress и SQLite/папку `media` напрямую в интернет. Порядок подготовки:

1. Создайте отдельную учётную запись для приложения и определите имя сайта и HTTPS-адрес. Ограничьте доступ учётной записи к исходникам, базе и `media`; делайте резервные копии базы **вместе** с PDF.
2. Настройте на прокси HTTPS, правильный `Host`, лимиты запросов на регистрацию и вход и передачу заголовка `X-Forwarded-Proto` **только от доверенного прокси**. Локальная защита входа хранится в памяти одного процесса и не заменяет лимиты на прокси при масштабировании.
3. Создайте секретный ключ один раз (не присылайте его в чат): `.\.venv\Scripts\python.exe -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"`. Сохраните в защищённой конфигурации сервера и установите переменные среды. Пример PowerShell ниже показывает форму, **подставьте свои значения**:

```powershell
$env:DJANGO_DEBUG = '0'
$env:DJANGO_SECRET_KEY = 'ВСТАВЬТЕ_СОБСТВЕННЫЙ_СЛУЧАЙНЫЙ_КЛЮЧ_НЕ_МЕНЕЕ_50_ЗНАКОВ'
$env:DJANGO_ALLOWED_HOSTS = 'learning.example.org'
$env:DJANGO_CSRF_TRUSTED_ORIGINS = 'https://learning.example.org'
$env:CERTIFICATE_BASE_URL = 'https://learning.example.org'
$env:DJANGO_TRUST_PROXY_SSL_HEADER = '1'
$env:WEASYPRINT_DLL_DIRECTORIES = 'C:\msys64\ucrt64\bin'
.\.venv\Scripts\python.exe manage.py check --deploy
.\.venv\Scripts\python.exe manage.py collectstatic --noinput
.\.venv\Scripts\waitress-serve.exe --listen=127.0.0.1:8001 --threads=4 learning_portal.wsgi:application
```

Запускайте эти команды **после** настройки TLS и прокси. `DEBUG=0` требует ключ от 50 символов, HTTPS редирект и защищённые cookies включаются автоматически. Не доверяйте `X-Forwarded-Proto`, если приложение доступно в обход прокси. Включайте HSTS (`DJANGO_HSTS_SECONDS`) только после успешной проверки HTTPS. Оставшиеся предупреждения `check --deploy` нужно разобрать на вашей фактической конфигурации; это не формальная гарантия безопасности.

Для небольшого пилота остаётся SQLite. Если число одновременных записей или задержки растут, планируйте PostgreSQL и отдельную миграцию данных. Waitress ограничен четырьмя потоками в примере; реальные CPU/RAM, число сотрудников и скорость PDF измеряются **на вашем сервере**, а не выводятся из локальных тестов.

## Что проверено и ограничения

- Django `check`, миграции, интеграционные тесты регистрации, последовательного доступа, пересдачи, PDF и публичной проверки.
- Вход по email (в том числе в админку) ограничен 10 ошибками на сочетание IP+email за 15 минут; регистрация — 30 запросами с IP за час. Лимит в памяти **каждого процесса**: на нескольких серверах нужен общий limiter на прокси.
- CSS/JS Bootstrap находятся в `static/vendor/bootstrap/`, лицензия — `static/vendor/bootstrap/LICENSE`. После `collectstatic` статику в боевом режиме отдаёт WhiteNoise.
- WeasyPrint при создании PDF может читать только QR, встроенный как PNG; внешние и локальные URL блокируются. Генерация PDF требует CPU и памяти и обычно выполняется один раз на сертификат. Она не удерживает транзакцию записи в БД; при ошибке выпуск можно повторить после исправления WeasyPrint.
- Администратор должен заменить демо своим проверенным содержанием. Локальный QR с `127.0.0.1` доступен только на том же компьютере. Для телефона нужен действительный сетевой HTTPS-адрес до момента выдачи сертификата.

Проверка уязвимостей зависимостей через `pip-audit` в среде разработки не завершилась: сервис PyPI не ответил до тайм-аута. На машине с доступом к PyPI выполните `.\.venv\Scripts\python.exe -m pip install pip-audit` и `.\.venv\Scripts\python.exe -m pip_audit -r requirements.txt`; затем установите исправления, если инструмент их найдёт. Проверка Django `check --deploy` не заменяет аудит внешних пакетов.

## Подтверждение почты

Новые и существующие сотрудники подтверждают email перед доступом к обучению. Подписанная ссылка действует 24 часа, GET показывает форму, POST подтверждает адрес; после подтверждения ссылка больше не действует. При смене email подтверждение сбрасывается. Повторная отправка ограничена минутным интервалом в базе и дополнительным лимитом запросов. Для разработки используется console.EmailBackend, для рабочего сайта — SMTP через переменные окружения. Полные команды cmd находятся в START_HERE.md. SMTP-пароль и база пользователей в ZIP не включены.

Демонстрационные видео в пяти модулях показываются как 30-секундные фрагменты исходных YouTube-роликов. После просмотра фрагмента целиком открывается следующий шаг.
