# Проверка Learning Portal перед пилотом

Проверено 25.09.2026 на локальном Django 5.2.17. Это обзор кода и тестов, не аудит сетевого сервера или проникновения.

| Область | Результат |
| --- | --- |
| Доступ к модулям и экзаменам | Проверяется на сервере по сданным попыткам; изменение URL и POST не открывает следующий модуль раньше времени. |
| PDF сертификата | Скачивание разрешено только владельцу. `/media/` не раздаётся Waitress/WhiteNoise. Публичная проверка показывает только выпущенный сертификат. |
| Генерация PDF | Версия WeasyPrint 70.0 включает актуальные исправления безопасности. Обработчик ресурсов принимает только встроенный PNG QR и отклоняет HTTP и `file://`. |
| Аутентификация | Email уникален без учёта регистра. Неудачные входы, включая админку, ограничены в памяти процесса; регистрация также ограничена. CSRF включён для форм. |
| Серверные настройки | При `DJANGO_DEBUG=0` нужен собственный секретный ключ, включены secure cookies и HTTPS redirect; для прокси заголовок схемы принимается только при явном включении. |
| Статика | Bootstrap лежит локально, production `collectstatic` и выдача WhiteNoise проверены. |
| Нагрузка | Кабинет с 16 курсами занял 4 SQL-запроса на локальном тесте. PDF создаётся по запросу один раз и не держит долгую транзакцию записи в SQLite. |

## Оставшиеся условия

- `check --deploy` требует решения по HSTS только после настройки HTTPS и всех поддоменов. Не включайте preload автоматически.
- Встроенный лимит входа действует отдельно в каждом процессе. Общий лимит на уровне доверенного прокси нужен при нескольких процессах или серверах.
- SQLite годится для пилота; число одновременных сотрудников, время PDF, RAM и нагрузку нужно измерить на реальном Windows Server. При заметных блокировках записи нужна миграция на серверную СУБД.
- Секретный ключ, права на `db.sqlite3` и `media`, резервное копирование, TLS и доступ к прокси на реальном сервере пока не проверены.
- Запуск `pip-audit` не смог получить ответы PyPI из этой среды (timeout). Скрипт и инструкция повторения проверки есть в `README.md`. Это не подтверждение отсутствия CVE в зависимостях.
- Содержание демонстрационного курса требует утверждения ответственным сотрудником, прежде чем использовать его для реальной сертификации.
